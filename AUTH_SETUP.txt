RPC ORDERS v13 — DISCORD ACCOUNT SETUP
======================================

WHAT IS INCLUDED
----------------
- Separate “Вход” and “Регистрация” tabs.
- Email OTP verification.
- “Оставаться в аккаунте” session persistence.
- Personal cabinet with nickname editing.
- Avatar upload/removal through Supabase Storage.
- Discord sign-in and Discord account linking.
- Google controls are removed from the website for now.

IMPORTANT BEFORE UPLOAD
-----------------------
Copy your PUBLIC values into auth-config.js:

window.RPC_AUTH_CONFIG = Object.freeze({
  supabaseUrl: "https://YOUR_PROJECT.supabase.co",
  supabasePublishableKey: "sb_publishable_YOUR_PUBLIC_KEY",
  avatarBucket: "avatars",
  oauthRedirectUrl: "",
  otpCooldownSeconds: 60,
  siteName: "RPC • RedPad Creator"
});

Never upload these to GitHub:
- sb_secret_...
- service_role key
- Resend re_... key
- Discord Client Secret

1. AVATAR STORAGE
-----------------
Supabase Dashboard -> SQL Editor -> New query.
Paste the entire SUPABASE_ACCOUNT_SETUP.sql file and press Run.

2. SUPABASE SITE URL
--------------------
Supabase -> Authentication -> URL Configuration.

Site URL:
https://rpc-order-website.onrender.com/

Redirect URLs:
https://rpc-order-website.onrender.com/
http://127.0.0.1:8080/
http://localhost:8080/

3. ENABLE DISCORD IN SUPABASE
-----------------------------
Supabase -> Authentication -> Providers -> Discord.
Enable Discord, then keep this page open for Client ID and Client Secret.

4. CREATE A DISCORD APPLICATION
-------------------------------
Open Discord Developer Portal:
https://discord.com/developers/applications

- Press New Application.
- Enter a name such as RPC Website.
- Open OAuth2.
- Add this Redirect URI exactly:
  https://kltlmugbsyavyauexxyv.supabase.co/auth/v1/callback

For another Supabase project use:
https://YOUR_PROJECT_REF.supabase.co/auth/v1/callback

- Copy Application ID / Client ID.
- Reset or copy Client Secret.

5. PASTE DISCORD KEYS INTO SUPABASE
------------------------------------
Supabase -> Authentication -> Providers -> Discord.

- Client ID: Discord Application ID.
- Client Secret: Discord Client Secret.
- Save.

The Client Secret stays only in Supabase. Never put it in auth-config.js.

6. ACCOUNT LINKING
------------------
Supabase -> Authentication -> Configuration / Providers.
Enable Manual identity linking.

This lets an email-authenticated user open the cabinet and press
“Привязать” next to Discord without creating a separate account.

7. TEST
-------
A. Sign in through Discord:
- Open the site.
- Press “Вход”.
- Press Discord.
- Approve authorization.
- The site should return to the cabinet.

B. Link Discord to an email account:
- Sign in using email OTP.
- Open the cabinet.
- Press “Привязать” next to Discord.
- Approve authorization.
- Discord should show “Привязан”.

C. Console checks:
window.RPC_AUTH.version
Expected: "2.1.0"

window.RPC_AUTH.client.auth.getUserIdentities()
Expected: email and/or Discord identity.

COMMON ERRORS
-------------
“Unsupported provider”:
- Enable Discord under Supabase Authentication -> Providers.

“Redirect URI mismatch”:
- Discord Developer Portal must contain the Supabase callback URL,
  not the Render website URL.

OAuth returns to the wrong page:
- Check Site URL and Redirect URLs in Supabase.

“Manual linking is disabled”:
- Enable Manual identity linking in Supabase Auth configuration.

SECURITY
--------
Do not trust accountId/accountEmail values sent by the browser for payments,
private order history, or permissions. A protected backend must verify the
Supabase access token before trusting the user ID.
