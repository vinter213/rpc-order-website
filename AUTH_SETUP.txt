RPC ORDERS v12 — ACCOUNT CABINET SETUP
=======================================

WHAT IS ALREADY IN THE SITE
---------------------------
- Separate “Вход” and “Регистрация” tabs.
- Email OTP code verification.
- “Оставаться в аккаунте” session persistence.
- Personal account cabinet.
- Nickname editing.
- Avatar upload/removal.
- Google and Discord sign-in buttons.
- Google and Discord identity linking from the cabinet.
- Account ID, email, nickname, and avatar are attached to ticket/review payloads.

IMPORTANT BEFORE UPLOADING v12
------------------------------
The archive contains a safe auth-config.js template without your Publishable key.
Copy the already configured values from your current auth-config.js into the new one:

window.RPC_AUTH_CONFIG = Object.freeze({
  supabaseUrl: "https://YOUR_PROJECT.supabase.co",
  supabasePublishableKey: "sb_publishable_YOUR_PUBLIC_KEY",
  avatarBucket: "avatars",
  oauthRedirectUrl: "",
  otpCooldownSeconds: 60,
  siteName: "RPC • RedPad Creator"
});

Never put these into the website or GitHub:
- sb_secret_...
- service_role key
- Resend re_... key
- Google Client Secret
- Discord Client Secret

1. CREATE THE AVATAR STORAGE
----------------------------
Supabase Dashboard -> SQL Editor -> New query.
Open SUPABASE_ACCOUNT_SETUP.sql, paste the entire file, and press Run.

It creates:
- public bucket “avatars”;
- 2 MB avatar limit;
- PNG/JPG/WEBP restrictions;
- RLS policies so a user can only change files inside their own user-ID folder.

2. SITE URL AND REDIRECT URLS
-----------------------------
Supabase -> Authentication -> URL Configuration.

Site URL:
https://rpc-order-website.onrender.com/

Redirect URLs — add both:
https://rpc-order-website.onrender.com/
http://127.0.0.1:8080/

Optional local alternative:
http://localhost:8080/

The site automatically uses its current origin as OAuth redirect URL.

3. ENABLE MANUAL IDENTITY LINKING
---------------------------------
Supabase -> Authentication -> Configuration / Providers.
Enable “Manual identity linking”.

This is required for the “Привязать Google” and “Привязать Discord” buttons in an already logged-in account.

6. EMAIL LOGIN AND REGISTRATION BEHAVIOR
----------------------------------------
“Вход” calls email OTP with shouldCreateUser=false.
An email without an existing account should not be silently registered.

“Регистрация” calls email OTP with shouldCreateUser=true and saves the nickname.

Both use the same secure email code verification.

7. TESTING
----------
A. Registration:
- Open “Регистрация”.
- Enter nickname and a new email.
- Enter the 6-digit code.
- The personal cabinet should open.

B. Sign in:
- Sign out.
- Open “Вход”.
- Enter the registered email.
- Enter the code.

C. Nickname:
- Open the cabinet.
- Change nickname.
- Reload the page — the new nickname must remain.

D. Avatar:
- Upload PNG/JPG/WEBP under 2 MB.
- Reload the page — the avatar must remain.
- If it fails, run SUPABASE_ACCOUNT_SETUP.sql and check Storage policies.

E. Google/Discord linking:
- Log in by email first.
- Press “Привязать” next to Google or Discord.
- Complete provider authorization.
- Return to the site and open the cabinet.
- The provider must show “Привязан”.

F. Console:
window.RPC_AUTH.version
Expected: "2.0.0"

window.RPC_AUTH.user
Expected: the logged-in Supabase user object.

window.RPC_AUTH.client.auth.getUserIdentities()
Expected: email plus linked Google/Discord identities.

8. COMMON ERRORS
----------------
“Bucket not found” / RLS error:
- Run SUPABASE_ACCOUNT_SETUP.sql.

“Unsupported provider” / provider not enabled:
- Enable Google/Discord in Supabase Providers.

OAuth returns to the wrong page:
- Set Site URL and Redirect URLs from step 2.

“Manual linking is disabled”:
- Enable Manual identity linking in Supabase Auth configuration.

Google/Discord callback mismatch:
- The provider callback must be the Supabase callback URL, not the Render website URL.

The website itself returns to Render/local through Supabase Redirect URLs.

9. SECURITY NOTE FOR FUTURE ORDER HISTORY
-----------------------------------------
The browser fields accountId/accountEmail/accountName are only convenient metadata and can be changed by a malicious client.
Do not use them alone for permissions, payments, private order history, or admin access.
For protected backend features, send the Supabase access token and verify it on the server before trusting the user ID.
